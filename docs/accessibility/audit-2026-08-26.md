# WCAG Accessibility Audit Report

**Date:** 2026-08-26
**Target:** Frontend Application (full app)
**Scope:** All components, views, and interactive patterns
**Standard:** WCAG 2.2 (Targeting Level AAA)

## Executive Summary

The full KainBain frontend demonstrates an exceptional, consistent commitment to accessibility. Every major interactive pattern — Modals, Comboboxes, Tablists, Menus, Toasts, Tooltips, the Kanban canvas, and the file explorer — is implemented using industry-standard WAI-ARIA patterns with full keyboard support, focus management, and live-region feedback. The application is **strongly compliant with WCAG 2.2 Level AA** and has a clear, bounded path to **Level AAA**.

A distinguishing strength: the codebase ships a **High Contrast theme** and a **Reduce Motion setting** in `UiPreferencesPanel`, plus a **skip-to-content link**, which are uncommon and highly valuable for accessibility.

## ⚠️ Findings Requiring Attention (for AAA / robustness)

### 1. Recurring — Hardcoded Low-Contrast Severity Colors

- **Files:** `WorkflowCanvas.jsx`, `TaskDetailOverlay.jsx`, `SystemGuideModal.jsx`, `ObservabilityDashboard.jsx`, `NowPlayingBar.jsx`
- **Violation:** WCAG 1.4.3 (Contrast - Minimum) / 1.4.6 (Contrast - Enhanced)
- **Issue:** Severity tags and status text use fixed hex pastel colors (e.g. `text-[#7bdb85]`, `#9acbff`, `#ffb77f`, `#a6e3a1`, `#94e2d5`, `#9aa7b5`, `#ff8383`, `#ffe0b2`) at 9–11px on dark surfaces.
- **Impact:** Low-vision users may not distinguish error/result/info log lines. `#9aa7b5` (muted slate) is the likeliest to fall below the 7:1 AAA threshold.
- **Recommendation:** Run a programmatic contrast check on every severity hex against its background (both the dark theme and the "High Contrast" theme). Adjust any value that cannot hit 7:1 for text and 4.5:1 minimum.

### 2. Reduced-Motion not honoring `prefers-reduced-motion` automatically

- **Files:** `NowPlayingBar.jsx` (`animate-pulse` dots), `TaskCard.jsx` (running pulse), `TaskDetailOverlay.jsx`, `ObservabilityDashboard.jsx` (`animate-ping`, `animate-pulse`), `Modal.jsx`
- **Violation:** WCAG 2.3.3 (Animation from Interactions) — best-practice; WCAG 3.0 motion assertions.
- **Issue:** `UiPreferencesPanel` exposes a **Reduce Motion** toggle, but the app does not auto-detect the OS `prefers-reduced-motion` setting.
- **Impact:** Users with vestibular disorders who set their OS to reduce motion still see pulsing/spinning animations.
- **Recommendation:** Gate the `animate-*` utility classes behind `@media (prefers-reduced-motion: reduce)` (or a Tailwind variant) in addition to the manual toggle.

### 3. Live updating regions not exposed as live regions

- **Files:** `ObservabilityDashboard.jsx` (widget grid + KPI/stats widgets auto-poll every 3.5s), `LiveConsoleWidget.jsx`, and the terminal logs in `TaskDetailOverlay.jsx` / `TaskDetailPage.jsx`
- **Good reference:** the Activity Console in `WorkflowCanvas.jsx` is the exemplar — it correctly uses `role="log"` + `aria-live="polite"` + `aria-label="Live agent activity stream"`.
- **Violation:** WCAG 4.1.3 (Status Messages) / ARIA live regions
- **Issue:** The Observability dashboard widgets, `LiveConsoleWidget`, and the TaskDetail terminal (marked only `role="region"`, no `aria-live`) update the DOM on a timer/stream, so screen readers won't announce significant changes.
- **Recommendation:** Mirror the WorkflowCanvas pattern: `role="log"` + `aria-live="polite"` + `aria-atomic="false"` on the streaming consoles (Observability and TaskDetail terminal), and a `role="status"` announcement for critical status flips (e.g. FAILED/RUNNING).

### 4. `SelectDropdown` — highlight relies on color only

- **File:** `SelectDropdown.jsx`
- **Violation:** WCAG 1.4.1 (Use of Color)
- **Issue:** Keyboard-highlighted option uses only a background shift (`bg-primary/20`). The *selected* item has a `✓`, but the *active descendant* does not.
- **Recommendation:** Add a non-color indicator to the highlighted item (e.g. `border-l-4 border-primary` or an arrow glyph).

### 5. `InfoTooltip` — `role="dialog"` for a non-modal tooltip

- **File:** `InfoTooltip.jsx`
- **Violation:** ARIA semantics (best practice) / WCAG 4.1.2 (Name, Role, Value)
- **Issue:** The popover is announced as `role="dialog"` with `aria-haspopup="dialog"`, but it is not modal and does not manage focus, so screen readers may announce it as a blocking dialog.
- **Recommendation:** For non-interactive help text use `role="tooltip"` + `aria-describedby`; reserve `dialog` for the interactive "pinned" mode.

### 6. Small focus targets in edge cases

- **Files:** `Header.jsx` ("New Project" modal close button is `p-1`), `ObservabilityDashboard.jsx` (⚙️ Manage Widgets and fullscreen buttons are `p-1`), `WorkflowCanvas.jsx` (stage-settings drawer close button is `p-1`)
- **Violation:** WCAG 2.5.8 (Target Size - Minimum, AAA 24px)
- **Impact:** Low-mobility users may struggle to hit very small icon buttons.
- **Recommendation:** Standardize a shared `min-w-[44px] min-h-[44px]` button class (already used elsewhere) for all close/icon buttons.

### 7. Keyboard focus visibility on custom interactive containers

- **File:** `TaskCard.jsx` (the `draggable tabIndex={0}` card root)
- **Violation:** WCAG 2.4.7 (Focus Visible)
- **Issue:** The draggable card is keyboard-focusable with Enter/Space to open, but does not add an explicit `focus-visible` ring; relies on the browser default outline.
- **Recommendation:** Add `focus-visible:ring-2 focus-visible:ring-primary` to the card root so the focused card is clearly visible.

### 8. Icon/emoji-only control lacks a robust accessible name

- **File:** `ProjectSettings.jsx` (`WorkflowManagementPanel` — the ✏️ rename-workflow button)
- **Violation:** WCAG 4.1.2 (Name, Role, Value)
- **Issue:** The rename button is a bare emoji (`✏️`) with only a `title` attribute and no `aria-label`, so its accessible name depends on `title` alone (less reliable than `aria-label`/visible text).
- **Recommendation:** Add an `aria-label="Rename workflow"` (matching the existing pattern used across the app) or visible text.

## 🚀 Next Steps for AAA Compliance

1. **Contrast Audit:** Run a programmatic check of every hardcoded severity hex (`#7bdb85`, `#9acbff`, `#ffb77f`, `#9aa7b5`, `#a6e3a1`, `#94e2d5`, `#ff8383`, `#ffe0b2`) against both dark and High-Contrast surfaces; target 7:1 for text.
2. **Reduced Motion:** Gate all `animate-pulse` / `animate-ping` / `animate-in` behind `prefers-reduced-motion: reduce` in addition to the existing manual toggle.
3. **Live Regions:** Wrap streaming log and telemetry panels in `role="log"` + `aria-live="polite"`.
4. **Focus / Target:** Standardize a 44px icon-button class and add explicit `focus-visible` rings to draggable card/column roots.
5. **ARIA semantics:** Switch non-modal tooltips from `role="dialog"` to `role="tooltip"` + `aria-describedby`.
