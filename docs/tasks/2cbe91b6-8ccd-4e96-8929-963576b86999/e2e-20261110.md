## Revoke-login: empty scan keeps the old list, ack stays ok

Phase A captured 77 real pi ids (real HOME); phase B ran with
`HOME=/tmp/empty-home-probe` (no login) with the prior slice seeded:

```
$ node /tmp/kb-e2e-revoke.mjs A && HOME=/tmp/empty-home-probe node /tmp/kb-e2e-revoke.mjs B
phaseA: captured 77 real pi ids
phaseB: real pi leg with revoked login yields 0 ids
ok: revoked login yields empty leg (honest empty, no throw)
[runner] Model discovery: 77 model(s) (pi:77); next refresh per modelDiscoveryIntervalMs.
ok: keep-old returns the same 77 ids
status after revoked round: count=77 ok=true
ack: [{"command":"requestModelRediscovery","ok":true,"detail":"discovered 77 model(s) (pi:77)"}]
ok: re-detect ack ok:true (cache kept, never a failure)
REVOKE CHECK PASSED
```

Note: a mid-process `$HOME` flip does NOT revoke (the pi SDK resolves the
home dir once per import), so the honest simulation is a fresh process with
an empty HOME — that is what phase B does. In production the same-process
path works because `listModels({refresh:true})` re-reads `models.json`
from disk, so a real credential revocation surfaces on the next round.
