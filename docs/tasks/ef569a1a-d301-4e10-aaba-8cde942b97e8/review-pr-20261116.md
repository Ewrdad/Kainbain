  capture with explicit `--out docs/tasks/<id>/<name>-proof.png`, then `xxd` /
  `file`, then `npm run check:binaries`) has no byte-handling step; the script
  writes bytes itself and now self-verifies. Capture examples point into the
  task folder per the survey note.

  the exact historic corruption independently in `/tmp` (UTF-8 round-trip of a
  valid proof): `xxd` showed `efbf bd50…`, `file` reported `data`. The guard
  exited 1 in seconds with:
  `guard-probe-corrupt.png: expected magic 89504e47, found efbfbd504e470d0a
  (… never create, edit, or restore binaries with text tools; re-capture via
  … or restore binary-safely via git checkout <ref> -- …)`.
  The untouched valid copy exited 0 (`1 binary checked`). The pre-commit hook
  is executable, `core.hooksPath=scripts/githooks` is active in this checkout,
  and the committed e2e hook tests prove a real `git commit` with a staged
  corrupt PNG is blocked (naming file + remedy), a valid one commits, and
  `--no-verify` bypass still works. True harness-level interception of
  text-tool writes is explicitly deferred (no clean interception point without
  touching live runs) — allowed: the criterion is "impossible OR fails fast".
- **AC3 — proof-hygiene gate unchanged.** Zero diff on the detector;
  `npm run check:proof-hygiene` green (`OK (11 known pre-existing issue(s)…)`),
  and the three historic `docs-sidebar-{collapsed,expanded,filtered}-proof.png`
