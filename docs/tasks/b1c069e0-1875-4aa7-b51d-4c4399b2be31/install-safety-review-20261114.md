# Install-safety review: binary-safe proof artifacts and repo-root scratch hygiene

Scope of the change (`git diff origin/main...HEAD`): 16 files — new `scripts/check-proof-and-hygiene.mjs` plus `tests/check-proof-and-hygiene.test.mjs`, new `scripts/allowlists/repo-root-files.json` and `scripts/baselines/proof-hygiene-known-violations.json`, `scripts/run-tests.mjs` (new `Proof Hygiene` branch + test registration), `package.json` (`check:proof-hygiene` script), `scripts/capture-screenshot.mjs` (comment only), `docs/agent-docs/GitGuidance.md` / `agents.md` (guidance), `tests/run-tests.test.mjs` (updated branch list). No dependency versions changed; no runtime tree changed.

## Would existing installs break on update?

No. Checked each install-breakage vector:

- **No new dependencies.** `package.json` only adds the `check:proof-hygiene` script entry; `dependencies`/`devDependencies`/`overrides` are identical to the base, and `package-lock.json` / `frontend/package.json` show no diff, so `npm ci` resolves the same tree. No `postinstall`/`preinstall`/`prepare` hooks exist or were added.
- **Runtime tree untouched.** The versioned installer (`scripts/lib/runner-install-root.sh`) copies only `runner/`, `api/`, `shared/`, `version.json`. `git diff --name-only origin/main...HEAD` shows zero changes under `runner/`, `api/`, `shared/`, `frontend/`, `deploy/`, `Dockerfile`, `publish.sh`, `startRunner.sh`; `runner/version.json` still reports `runnerVersion 0.1.0` and `package.json` still `1.0.0`. An update therefore lays a byte-identical runtime and cannot break installed runners at boot. No deletions (`--diff-filter=D` empty).
- **stdlib-only, engine-compatible.** The checker imports only `node:fs`, `node:path`, `node:url` and uses no `.at(` or other post-Node-20 APIs. Engines require `^20.19.0 || >=22.12.0`, so it runs on every supported install. Importing it does not execute the scan (guarded by `invokedDirectly`); `node --check` passes on all three touched scripts.
- **Passes on the unmodified tree.** `node scripts/check-proof-and-hygiene.mjs` exits 0 in ~0.1s with `✓ proof artifacts and repo-root hygiene OK (11 known pre-existing issue(s) recorded in the baseline)`, and `npm run check:proof-hygiene` exits 0 with the same line. All 28 tracked root files (`git ls-files` depth-1) evaluate `isRootScratch` false against the empty allowlist, so no legitimate root file false-fails; the 11 baselined corrupt PNGs were verified corrupt on HEAD (`xxd -l 8` → `efbf bd50…`) and are covered same-path/same-bytes. The only new execution on `deploy.sh --prod` (via `./run-tests.sh --no-canary`) therefore does not block updates on a clean tree; it fails only on deliberately bad fixtures.
- **Acceptance rehearsal holds.** In throwaway `--root` fixture trees: valid PNG (`89504e47`) + clean root → exit 0; corrupt PNG (`efbfbd…`) → exit 1 naming the path with `expected magic 89504e47, found efbfbd…` plus the remedy; root `rt.mjs` → exit 1 naming the file and the `rt.*` pattern plus the remedy. `node --test tests/check-proof-and-hygiene.test.mjs` passes 63/63 and `node --test tests/run-tests.test.mjs` passes 35/35, including the new `Proof Hygiene` wiring assertions.
- **No gate regressions.** `node --test tests/install-runner-wrapper.test.mjs` passes 8/8 both with and without `KAINBAIN_RUNNER_INSTALL_ROOT` set (the historical 3 failures in the two `automated-tests-failure-20261114-*` reports pre-date the 19:52 `sandboxEnv` fix and are not caused by this change). `node scripts/check-doc-links.mjs` passes (71 files), and `check-one-function-per-file` / `check-jsdoc-example` both report PASS on the new script.
- **No output-contract break.** The gate gains one branch (12→13 with canary, 11→12 with `--no-canary`); `run-tests.test.mjs` was updated to pin the new count and `deploy.sh` consumes exit codes, not line counts. `scripts/capture-screenshot.mjs` changes are comments only, so the binary-safe capture path is unchanged.

## Verdict

Safe to update: existing installs resolve the same dependency tree, receive a byte-identical runtime tree, and the single new gate execution passes on the current tree in subsecond time. Intentional failures (corrupt proof, stray root scratch) are the feature, not breakage.
