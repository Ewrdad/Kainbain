## 3. Guiding Principles & Standards Alignment

### "Make Change Easy, Then Make the Change" (Kent Beck)
1. **First (Make Change Easy):**
   - Build a complete, machine-readable inventory of root `*.md` files and every inbound reference to them (code, tests, scripts, workflows, other docs).
   - Run the existing gates (lint-agents-md, check-doc-links) to establish a numbered, reproducible baseline before touching anything.
   - Classify each root Markdown file as `KEEP-LIVE`, `KEEP-BY-POLICY`, or `DELETE-UNUSED` with explicit evidence.
   - Add a small, read-only audit helper (optional) so future regressions are caught cheaply.
2. **Then (Make the Change):**
   - Delete `DELETE-UNUSED` files with `git rm` in a single, reviewable batch.
   - Remove any now-empty directories.
   - Fix accidental artifacts committed to root (session transcripts) and prevent recurrence via `.gitignore`.
   - Keep all `KEEP-*` files untouched so no live links break.

### Reliability & Risk Alignment
- **Escalation Ladder Level 1 (Preventative Design):** Static detection at the earliest gate prevents "cleanup by guesswork" and avoids deleting something that a workflow references untracked.
- **Fail-safe:** Markdown deletion cannot break runtime. The only regression surface is doc/link gates; both are run before and after.

### KainBain Code Standards Alignment
- **Readability over cleverness:** Use plain filenames and explicit evidence (reference counts) rather than heuristic pattern matching.
- **Co-location of tests:** Verification uses existing scripts under `scripts/` and `tests/`; no new runtime code is required.
- **Pure, deterministic audit outputs:** Any helper prints sorted, stable output with paths and reference counts.
