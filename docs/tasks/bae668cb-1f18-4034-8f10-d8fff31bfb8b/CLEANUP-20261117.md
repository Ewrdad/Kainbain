# Cleanup stage notes (2026-11-17)

Scope: harden + standards-align the end-state-C implementation landed by the
previous stages, with zero behavior change intended. All gates re-run after
every edit; mutation probes re-run after the cleanup.

## What changed in this stage

- `frontend/src/components/docs/docsSections.js` split per the
  `check:one-function-per-file` gate (it FAILED on the prior HEAD: the file
  had gained two top-level named functions and is not in the grandfather
  allowlist). Now:
  - `docs/deriveSectionOrder.js` — one function, labelled inputs
    `({ index, docs })`, ids de-duplicated in both the index path and the
    first-appearance fallback (a malformed `sections: ['a','a']` index can
    no longer render one sidebar group twice / trip React duplicate keys).
  - `docs/resolveSectionLabel.js` — one function, labelled inputs
    `({ index, section })`, always returns a string (non-string section
    degrades to `''`) and uses an own-property check so prototype names
    (`constructor`, `__proto__`) can never leak a non-string label.
  - `docsSections.js` keeps only `DOCS_SIDEBAR_STORAGE_KEY` (a const —
    passes the one-function gate). Tests split next to each file:
    `deriveSectionOrder.test.js`, `resolveSectionLabel.test.js`,
    `docsSections.test.js` (storage key only).
  - `DocsView.jsx` imports the two helpers from their own files; call sites
    use the labelled-input shape.
- `api/siteDocs.frontendParity.test.js` — the "no second taxonomy copy"
  guardrail now scans all three frontend docs modules (not just
  `docsSections.js`), so a hand-maintained `DOC_SECTION_ORDER` /
  `DOC_SECTION_LABELS` re-added to ANY of them turns red with a fix message.
- `api/agentGuide.js` — GET /docs purpose text no longer pins the four
  literal section ids (another rename touch-point removed) and now
  describes the real payload `{ sections, sectionLabels, docs }` (the old
  text described a bare array — stale since before this branch).
- `site-docs/api-reference.md` — GET /docs row updated to
  `{ sections, sectionLabels, docs }`.
- `api/routes/docs.test.js` — asserts every shipped section carries a
  non-empty string label in `body.sectionLabels` (invariant, not a literal
  copy; exact values stay pinned single-source in the parity test).
- `api/siteDocs.js` — REQUIRED RENAME PROCEDURE step 6 now notes that a few
  test literals intentionally pin current ids as tripwires and are updated
  as part of a rename.

  positional), matching the API-side helpers.

  PASS, 835 files scanned — was FAIL on the prior HEAD).
