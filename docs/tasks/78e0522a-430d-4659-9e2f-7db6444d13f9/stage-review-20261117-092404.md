## Human correction (assets/19126.png) — verified fixed at HEAD

Complaint: *"it's comparing a hash to a build and the latest image seems to not be
flagged as latest in the drop-down".*

- **Hash vs build.** At screenshot time the sha-mismatch warning printed the raw
  backend identity next to the runner hash (`fbcf844` vs `1.0.0-28aac94` — a
  version-tagged image tag, i.e. a build, not a hash). Current HEAD fixes this:
  `extractBuildSha` pulls the commit sha out of both sides
  (`extractBuildSha('1.0.0-28aac94') => '28aac94'`), so the warning now reads
  *"built from commit fbcf844 but the backend runs commit 28aac94"* — sha-to-sha.
  Both `fbcf8442…` and `28aac94…` are real commits in this repo, so the comparison is
  meaningful. Verified by executing `runnerBuildWarning(liveRunner, '1.0.0-28aac94')`.
  Test `compares a version-tagged backend build sha-to-sha, not hash-to-tag` asserts
  the message matches `/28aac94/` and `not.toMatch(/1\.0\.0-28aac94/)`.
  Additionally, hashes and all-digit build stamps can never parse as versions on
  either side: frontend `versionTuple` rejects `/^[0-9a-f]{7,40}$/i` (mirroring the
  backend `SHA_LIKE_RE`), so `canonicalRunnerVersion('fbcf8442…') === null` and
  `canonicalRunnerVersion('20261117') === null` — verified by execution; a runner
  reporting a hash as its version gets no badge, no warning, no phantom dropdown
  option (test `stays silent when the running version is a build hash, never
  hash-vs-build`).
- **Latest not flagged in the drop-down.** Current `versionSelectorOptions` labels
  every option with `(latest)` / `(running)` flags computed on **canonical** versions,
  and the `Latest` option itself is labelled with the resolved release. Executed with
  the live record: options `[{value:'0.1.0', label:'0.1.0 (latest, running)'}]`,
  `selectedValue 'latest'`, closed select renders `Latest (0.1.0)`. Executed with a
  version-tagged recommended knob (`1.0.0-28aac94`): the dropdown collapses it to one
  canonical row `1.0.0 (latest)` — the raw tag never appears as a phantom option
  (component test `flags the newest release as (latest) even when the recommended
  value is a build tag` asserts exactly
  `['latest=Latest (0.3.0)','0.3.0=0.3.0 (latest)','0.2.0=0.2.0 (running)','0.1.0=0.1.0']`
  and `not.toContain('abc1234')`).
