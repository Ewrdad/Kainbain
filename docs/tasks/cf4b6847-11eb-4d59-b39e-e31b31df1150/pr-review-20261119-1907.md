conflict region, in `api/projectStore.barrel.test.js` (the expected-exports

`normalizeDocsRepoPointers` / `normalizeDocsRepoSettings` on adjacent lines.

`api/flow/runnerRoutes.js`, `api/project/index.js`, `api/projectStore.js`,
`api/routes/projects.js`, `runner/daemon.js`) auto-merge cleanly — notably
the merged `api/project/index.js` already carries BOTH our
`normalizeBaseBranchUpdate` export and their docsRepo exports, so the test
file is the only thing standing in the way.

Resolution is trivial (keep all three lines in alphabetical order) but it is
a change to `api/`, which this docs-only stage is forbidden from making —
any such edit would be discarded by the engine. Passing this stage would
send the task straight back into the merge stage to fail identically, so the
honest verdict is FAIL with the fix scoped to that one resolution plus a
re-run of the barrel test.
