## Executive summary

KainBain is a **mature, well-tested local-first AI task orchestrator**
that is close to production but **not shippable from this checkout
today without one fix**: `npm run test --prefix api` fails at startup
(exit 1, `ERR_MODULE_NOT_FOUND: Cannot find package 'vite'` imported
by vitest). Everything else in the fast gate is green. The failure is
in test runner wiring (an undeclared peer dependency under
`legacy-peer-deps=true`), not in application code — but a red default
gate is a red default gate.

## 1. How close to production?

**Close, with two blockers and two known gaps.**

### Green (verified today)

- **Frontend unit tests: 259 files / 3556 tests, all pass** (`npm run
  test --prefix frontend`, exit 0).
- **Lint: 0 errors** in both packages (`npm run lint:api`,
  `npm run lint:frontend`). 323 api + 152 frontend warnings, all in
  the two known noisy rules (`security/detect-object-injection`,
  `security/detect-non-literal-fs-filename`) — same false-positive
  classes as the August report.
- **Fast gate (no canary): 8 of 9 branches PASS** — frontend tests,
  both lints, frontend build, security-script tests, dependency audit,
  harness self-tests, container (static) tests.
- **Deploy machinery is serious:** `deploy.sh` runs a
  final-test-suite gate, a separate serial canary-e2e gate, security
  scans, build + staging verification, an atomic release archive with
  rollback (`--rollback`), and aborts if the tree changed
  mid-gates. Docker path is turnkey (`docker compose up -d`, no
  credentials needed, degrades honestly without keys).
- **Config discipline:** every tunable is declared once in
  `api/config/schema.js`, validated at boot, and the 440-line
  `.env.example` is generated from the schema — one source of truth,
  grouped by concern.

### Red (verified today)

1. **API unit tests do not run in this checkout.** `npm run test
   --prefix api` exits 1 before any test executes:
   `Cannot find package 'vite' imported from
   api/node_modules/vitest/.../index.DpLw24bj.js`.
   Cause (confirmed, not guessed): `api/package.json` declares
   `vitest` but not its peer `vite`, and root `.npmrc` sets
   `legacy-peer-deps=true` (kept deliberately per `DEPRECATIONS.md`
   spike 3 because two eslint plugins still cap at ESLint ≤ 9). So no
   `vite` is installed under `api/node_modules`, and vitest 5 cannot
   start. The frontend is unaffected because it declares `vite`
   directly. The October PR reviews claim "api suite green," so this
   is likely a fresh-checkout/reinstall artifact — but it reproduces
   deterministically here and the default `npm test` gate is red
   because of it. **Fix options:** add `vite` (pinned to the
   `^6.0.0 || ^7.0.0 || ^8.0.0` peer range vitest asks for) to
   `api` devDependencies, or document a pinned Node 24 +
   `npm run setup` flow that restores a hoisted copy. Either way,
   re-run the full gate after.
2. **Canary E2E not re-verified today** (serial Playwright suite,
   ~7 min; skipped for time). Last evidence: October PR review
   reports the full gate green including the 375 px / 6-tag mobile
   search-bar e2e; August report had 38/42 canary passing with 3
   stale-visual + 1 moderate WCAG `region` landmark failure in
   Settings. Treat the accessibility item as still open until a
   canary run says otherwise.

### Known gaps (from the 2026-08-26 readiness report, unchanged)

- **Single-host backup:** only task reports (via the SilverBullet
  `docs` symlink) get the hourly git backup; per-project
  `.kainbain/project.json` configs under `~/projects/*` are not
  backed up, and there is no off-machine backup. The app survives a
  process crash (systemd auto-restart, rollback archive) but not a
  dead disk.
- **Working-tree hygiene is currently fine:** `git status --short`
  is clean today, unlike August's 38-file drift. Good.

## 3. New-starter experience

Tested by reading, not by a fresh clone (no destructive reinstall was
run). From the docs alone, the path is genuinely welcoming:

1. **Three named paths** (Docker / native / corporate laptop) right
   at the top of `README.md`, each cold-starting from a public clone
   with no credentials. The `PORTABLE_DEPLOYMENT.md` guide covers
   clone → run → verify, including the storage-sanity checklist from
   the empty-board incident class.
2. **One-command setup:** `npm run setup` installs all four trees in
   order and both Playwright Chromium builds, failing fast with the
   step named. Per-OS browser flags (Linux `--with-deps` with
   fallback) show real care.
3. **In-app first-time guide** (`#/docs/first-time-setup`, also
   served as `GET /docs/first-time-setup`) walks install → configure
   → run → verify → first project.
4. **Single-source env docs:** copy `.env.example` → `.env`, fill
   secrets only; every knob explained at its schema default.

Friction a newcomer will still feel:

- **Heavy first install:** four `npm install`s plus two Chromium
  downloads. Unavoidable given the split packages, but the setup
  script owns it — don't try to hand-roll the installs.
- **The default `npm test` runs the ~7-minute canary suite.**
  Opt out with `--no-canary` / `KAINBAIN_SKIP_CANARY=1`, but know the
  deploy gate runs it anyway — the heaviness is deliberate
  (post-#KB-0417 policy: regressions surface early, not at deploy).
- **Node version:** `.nvmrc`/`.node-version` say 24 and `engines`
  requires `^20.19.0 || >=22.12.0`. This machine runs Node 26
  (satisfies `>=22.12.0`, but is outside what the team tests on) —
  and the API vitest failure above may or may not reproduce on
  Node 24. A newcomer on Node 26 should expect minor surprises.
- **Homelab-isms leak through:** SecObserve uploads, `*.home`
  origins, systemd units, and the `docs/` symlink into a personal
  SilverBullet space (see note below) all assume the author's
  environment. The Docker path papers over most of this — recommend
  it first.

## 4. Code quality and cleanliness

**High — this is the strongest area.**

- **Scale with coverage to match:** `api` has 119 top-level modules
  with 86 colocated test files; `frontend/src` has 512 files with
  259 test files (3556 tests). Colocated `*.test.js(x)` next to every
  module plus contract/integration suites (`agentRunner.contract`,
  `eventBridge.contract`, `workflowConsistency.contract`,
  git-isolation integration tests) is the established pattern, and
  the October reviews show it being extended, not eroded (pure
  helpers extracted to `unifiedSearchBarUtils.js` with 23 edge-case
  tests; fail-safe prop normalization; `useId` per-instance DOM ids).
- **Conventions are written down and followed:** `MARK:` /
  `@description` / `@example` JSDoc headers per KB Code Standards,
  black-box component tests, responsive-hiding via CSS only with DOM
  retained for a11y. The review summaries explicitly check all four
  (plan fidelity, standards, modifiability, no regressions).
- **Zero lint errors, zero TODOs, zero drift:** today's working tree
  is clean and the warning profile matches the documented baseline.
- **Dependency hygiene is the best I've seen in a small repo:**
  `DEPRECATIONS.md` is a real inventory (severity, owner file,
  action, status, revisit dates), not a wish list; depcheck,
  no-deprecation build gates, and the audit gate all run in CI/deploy.
- **Nits (non-blocking):** the repo root carries some process
  residue — `agent-docs/`, `scratch/`, `test-results/`,
  `.vitest/`, per-task review summaries (`REVIEW_SUMMARY.md`,
  `PR_REVIEW_SUMMARY.md`) committed at root. Harmless, but a
  newcomer meets clutter before code. The `docs/` symlink pointing
  outside the repo (personal notes space) is the biggest structural
  smell: this very report lands in the author's SilverBullet vault,
  not in version control — consider a repo-local `docs-local/` or
  confirming the symlink resolves for every contributor.
- **Git history is noisy** (auto-commit messages per task stage),
  which makes `git log` archaeology harder than the code deserves.
  Cosmetic; the in-docs task reports compensate.
