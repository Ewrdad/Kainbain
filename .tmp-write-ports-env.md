# Ports & Environment Variables
- **Section:** `working-with`
- **Slug:** `ports-env`
- **Order:** `20`
- **Audience:** working-with
- **Summary:** How KainBain uses local TCP ports and which environment variables you can set — and when to leave the defaults alone.

KainBain is a small distributed system that runs on your machine. Each piece
needs its own TCP port so the pieces can talk to each other. This page lists
the ports and the important environment toggles.

> **Beginners:** you can leave every value at its default and KainBain will
> work. Change a value only if something else already uses that port or you
> are deploying.

## 1. Port map — the pieces

| Piece | Default | What it is |
| --- | --- | --- |
| API backend | `3100` | The brain. Stores projects and runs agent stages. |
| Frontend | `5173` | The browser dashboard that talks to the backend. |
| Dispatcher (optional) | `3101` | The runner router. Only used when `KAINBAIN_RUNNER_DISPATCH=1` — see [#/docs/add-new-runner]. |
| OpenCode server | `4096` | The Opencode harness server. Only needed if your project uses the Opencode harness; it can be shared or per-project. |

All four defaults are configurable, but it is simplest to keep them.

---

## 2. How to tell pieces a different port

You only need this if a port is already taken (for example `3100` is used by
another app).

The API reads two variables from its environment. The frontend always calls the
backend over the browser (it uses a relative URL), so setting the backend port
on the backend is enough to keep them in sync.

- `KAINBAIN_PORT` — API backend
- `KAINBAIN_RUNNER_DISPATCH_PORT` — dispatcher

You do not need to set `KAINBAIN_API_URL` any more — the frontend is built to
work from any origin and no longer uses this variable.

If you do change ports, you must set the same variable on every piece that
reads it. That includes any remote runners (see [#/docs/add-new-runner]).

## 3. Important `KAINBAIN_*` environment variables

KainBain reads variables with the `KAINBAIN_` prefix. Only the `KAINBAIN_*`
family is loaded by KainBain — other variables (for example `OPENAI_*`,
`OPENCODE_*`) are harness-specific and handled by those tools.

`KAINBAIN_*` variables are validated at boot by the server. Invalid values
prevent the server from starting, which is safer than silent fallbacks.

The full list with defaults lives in `api/config/schema.js` and is exposed at
runtime by the API at [GET `/status/config`](#/docs/api-reference). The table
below groups only the user-facing core. See the API docs for the complete list.

### General behaviour

| Variable | Default | What it does |
| --- | --- | --- |
| `KAINBAIN_DEFAULT_HARNESS` | `pi` | Default harness for new projects. |
| `KAINBAIN_DEFAULT_HARNESS_MODEL` | _(empty)_ | Default model alias for the harness above. |
| `KAINBAIN_DEFAULT_CODEX_MODEL` | `gpt-5.1-codex` | Fallback model name for the Codex harness. |
| `KAINBAIN_APP_NAME` | `KainBain` | Name shown in API responses. |
| `KAINBAIN_DOCS_TITLE` | `Kainbain Docs` | Title for the in-app docs viewer. Not security-relevant. |
| `KAINBAIN_BROWSER_ENABLED` | `true` | Allow the runner to use a browser. |
| `KAINBAIN_MAX_STAGE_COUNT` | `200` | Maximum stages in a pipeline. |
| `KAINBAIN_MAX_STAGE_NAME` | `120` | Maximum characters in a stage name. |
| `KAINBAIN_SYSTEM_SETTINGS_MAX_LEN` | `6000` | Maximum length of project system settings. |
| `KAINBAIN_RETROSPECTIVE_MAX_LEN` | `20000` | Maximum length of retrospective notes. |
| `KAINBAIN_GITLAB_BASE_URL` | `https://gitlab.com` | Base URL for the GitLab integration. |
| `KAINBAIN_CUSTOM_STATE_FOLDER_CONFIGURED` | _(empty)_ | Set after you configure a custom state folder location (advanced). |
| `KAINBAIN_LOG_LEVEL` | `INFO` | Server log level. |
| `KAINBAIN_LOG_MAX_BYTES` | `10485760` | Maximum bytes before a log rotates. |
| `KAINBAIN_LOG_MAX_FILES` | `5` | Number of rotated log files kept. |
| `KAINBAIN_LOG_MAX_AGE_DAYS` | `30` | Maximum age of logs kept. |
| `KAINBAIN_PROJECT_REDISCOVERY_INTERVAL_MS` | `60000` | How often the server re-discovers projects on disk. |
| `KAINBAIN_STAGE_TIMEOUT_MS` | `3600000` | How long a stage may run before it is considered timed out (1 hour). |

### Operational / security (required in production)

The following variables exist to harden the app and must be set when the
server starts. In the default local install they may be empty while you are
getting started, but never leave them this way outside your own machine:

| Variable | What it does |
| --- | --- |
| `KAINBAIN_LOGIN_CODE` | Static access code gate (see [#/docs/api-reference]). |
| `KAINBAIN_SALT` | Salt used to hash the login code. |
| `KAINBAIN_JWT_SECRET` | Secret used to sign session tokens. |
| `KAINBAIN_AUTH_PEPPER` | Extra pepper used for auth hashing. |
| `KAINBAIN_RUNNER_JOIN_TOKEN` | One-time credential for approving new runners. |
| `KAINBAIN_CORS_ORIGINS` | Allowed browser origins. |
| `KAINBAIN_RUNNER_CORS_ORIGINS` | Allowed origins for runner traffic. |
| `KAINBAIN_TRUST_PROXY_COUNT` | Number of trusted proxies in front of the server (for rate-limit IP). |

### Harness binaries

These point the runner at the right binary if it is not on your `PATH`:

| Variable | Default binary | Notes |
| --- | --- | --- |
| `KAINBAIN_CLAUDE_BIN` | `Muse` | Muse harness. See [#/docs/harness-muse] (soon: [#/docs/link-runner-muse]). |
| `KAINBAIN_MUSE_BIN` | `codex` | Codex harness binary. |
| `KAINBAIN_PI_BIN` | _(auto)_ | Pi SDK harness (usually needs no change). |
| `KAINBAIN_PI_MODEL` | _(empty)_ | Optional override model for Pi. |
| `KAINBAIN_PI_CLI_PATH` | _(empty)_ | Path to a Pi CLI binary, if needed. |
| `KAINBAIN_PI_CWD` | _(empty)_ | Working directory override for Pi. |
| `KAINBAIN_OPENCODE_BIN` | `opencode` | The Opencode CLI. |

Other harness variables, such as `KAINBAIN_MUSE_BIN`, are described per-harness
in that harness's link guide.

### Runner variables

See [#/docs/add-new-runner] for a focused runner guide and `runner/README.md`:

| Variable | What it does |
| --- | --- |
| `KAINBAIN_RUNNER_BACKEND_URL` | Backend URL the runner connects to (example `http://127.0.0.1:3100`). |
| `KAINBAIN_RUNNER_DISPATCH` | `1` to use dispatch mode (routes every runner through a dispatcher). |
| `KAINBAIN_RUNNER_HARNESS` | Which harnesses this runner offers (example `pi,muse`). |
| `KAINBAIN_RUNNER_MODELS` | Override the advertised model list. |
| `KAINBAIN_RUNNER_ID` | An explicit runner identity. |
| `KAINBAIN_RUNNER_MODEL_DISCOVERY_INTERVAL_MS` | How often the runner probes model availability. |
| `KAINBAIN_RUNNER_HEARTBEAT_MS` | Heartbeat interval. |

### Notifications

Optional. See [#/docs/push-notifications]:

| Variable | What it does |
| --- | --- |
| `KAINBAIN_VAPID_PUBLIC_KEY`, `KAINBAIN_VAPID_PRIVATE_KEY` | Web-push notification keys. |
| `KAINBAIN_NOTIFICATION_ORIGIN` | Origin (URL) shown for notifications. |

### Dispatch mode

Only needed when you run KainBain in the multi-machine layout described in
[#/docs/add-new-runner]. Most local installs do not need this:

| Variable | What it does |
| --- | --- |
| `KAINBAIN_RUNNER_DISPATCH_PORT` | Dispatcher listen port (default `3101`). |
| `KAINBAIN_RUNNER_DISPATCH_BACKEND_URL` | Backend URL as seen by runners (passed to new runners). |
| `KAINBAIN_RUNNER_DISPATCH` | `1` to use dispatch mode. |

## 4. The `PROJECTS_ROOTS` variable

This variable controls where new projects are kept. It is deliberately not a
`KAINBAIN_*` variable so that the shell can set it freely before launching
KainBain.

- Default: `~/.kainbain/projects`
- You may give multiple roots separated by the OS path delimiter (`:` on
  Unix/macOS, `;` on Windows).
- Existing project adoption is a separate flow — see
  [#/docs/existing-projects].

## 5. Changing a variable — the right way

1. Edit the environment for the process that reads it (`.env` file or the
   installer's prompt).
2. Restart that process. Environment changes do not take effect until a restart.
3. Re-run the quick verify below and confirm the UI reflects the change.

> Restart after every env edit. The app does not hot-reload environment
> variables.

## 6. Quick verify

1. `curl -s http://localhost:3100/status | jq`
2. `curl -s http://localhost:3100/status/config | jq .config`
3. If anything is bound to a non-default port or address, those URLs must use
   that value.
4. Open Settings in the UI and confirm the value you changed is visible where
   applicable.

## 7. Harness auth keys

Model auth keys (for example OpenAI or Anthropic API keys) are not `KAINBAIN_*`
environment variables. They are stored only on the machine where the harness
actually runs. The backend never handles them, so they are not documented here
(see the per-harness docs).

## 8. Troubleshooting — common env issues

- “`KAINBAIN_* is not in environment`” warnings at boot: some operational
  variables are missing. They must be set as described in
  [#/docs/api-reference].
- A port “refuses connection”: a process expected a different port than it was
  given. Use `lsof -i -P` / `ss -lptn` to see which process owns it.
- Empty runners table even though a runner process is running: the runner's
  `KAINBAIN_RUNNER_BACKEND_URL` does not match the backend you are looking at,
  or its join credential is wrong.
- Model list empty: the harness binary is missing, misconfigured, or the server
  was just installed. Wait for discovery, or check the harness link guide for
  that runner.

See [#/docs/getting-started] to start, then [#/docs/install-run],
[#/docs/add-new-runner], or [#/docs/existing-projects] for your next step.
